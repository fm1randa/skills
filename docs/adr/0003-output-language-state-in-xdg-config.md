# Keep the output-language state in `~/.config/output-language`, where an external app may write it

The `output-language` skill keeps its state in `$XDG_CONFIG_HOME/output-language` (`~/.config/output-language` by default): a `settings.json` with the named Language Profiles and the Default Profile, and one Session Lock file per session under `sessions/`. The Reminder hook reads those files on every turn, so a session follows the Default Profile from its first reply and a change takes effect on the next prompt, with no skill run at session start. The shapes are documented in [the skill's setup reference](../../skills/output-language/references/setup.md).

The consequence worth recording is not the directory but the ownership. **The skill owns the file contract; any other program is a client of it.** Aidiom, a macOS menu bar app living in its own repo, writes the same files to switch the default and pin profiles to live sessions. That is deliberate: the state is a small, documented, plain-JSON contract precisely so a native app can drive it without the skill knowing the app exists. It also means the contract is now a published interface — the three lock states, the "no file means inherit" rule and the attachment fingerprint cannot change shape here without breaking a program in another repo. A state directory outside `~/.claude` is what makes that honest: this is not Claude Code's private data, and it is not the app's data either.

We rejected three alternatives. **Keeping the default in `~/.claude/CLAUDE.md`** (a startup line that ran the skill and `@`-attached a style-guide PDF) makes every change a hand edit of a global instructions file, burns the whole PDF into context at session start, and cannot be read or written safely by anything else. **Letting the app edit CLAUDE.md** trades that for worse: an app rewriting the user's own prose file, with no schema to validate and a merge conflict against the user's every keystroke. **Shipping the app inside this repo** was rejected because this repo distributes bare Skills through the `skills` CLI ([ADR 0001](0001-distribute-via-skills-cli-and-symlinks.md)) and a Swift menu bar app has nothing to do with that pipeline — the file contract is a far cheaper seam between the two than a shared release. The cost we accept: two repos must agree on one JSON shape, and this skill can no longer treat its state files as a private implementation detail.
